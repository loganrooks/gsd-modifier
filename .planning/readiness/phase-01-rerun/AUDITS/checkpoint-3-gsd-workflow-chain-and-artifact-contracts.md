## Phase-Critical Workflow Map

- [e:c:i] `1. Steering capture lives in discuss-phase, not in planning.` `discuss-phase.md` loads project canon and prior phase contexts, checks for existing context/plans, derives `canonical_refs` and `future_awareness`, writes a resumable `*-DISCUSS-CHECKPOINT.json` after each area, then writes the canonical `*-CONTEXT.md`, the audit-only `*-DISCUSSION-LOG.md`, and a `STATE.md` session record before optional auto-advance. Sources: `.codex/get-shit-done/workflows/discuss-phase.md:258-319,322-376,461-487,893-927,938-1217,1235-1272`; `.codex/get-shit-done/templates/context.md:1-12,64-80,93-152`.
- [e:c:i] `2. There is a secondary steering entry in plan-phase.` The PRD express path in `plan-phase.md` can generate `CONTEXT.md` itself, but it still has to emit the same steering artifacts: phase boundary, locked decisions, mandatory `canonical_refs`, `future_awareness`, specifics, and deferred ideas. This is an alternate entry path into the same contract, not a separate contract family. Sources: `.codex/get-shit-done/workflows/plan-phase.md:92-213`.
- [e:c:i] `3. Planning in exploratory mode treats missing context as a hard contract failure unless explicitly overridden.` `plan-phase.md` stops when `DISCUSS_MODE` is `exploratory` and no `CONTEXT.md` exists, unless `--allow-no-context` is supplied, and it explains that this weakens future-aware guarantees and removes context-derived `canonical_refs` and preserve-seam input. Sources: `.codex/get-shit-done/workflows/plan-phase.md:215-252`.
- [e:c:i] `4. Canonical refs are a real handoff surface, not a note-taking nicety.` `discuss-phase.md` accumulates them across roadmap, canon, scout, and user prompts; `plan-phase.md` resolves them from `CONTEXT.md` and injects them into researcher, planner, and checker `<files_to_read>` blocks as mandatory source-of-truth inputs. Sources: `.codex/get-shit-done/workflows/discuss-phase.md:468-476,1031-1051`; `.codex/get-shit-done/workflows/plan-phase.md:291-304,370-375,677-678,827-833`.
- [e:c:i] `5. Research is integrated into the phase chain even when the standalone workflow exists.` `research-phase.md` and `plan-phase.md` both spawn `gsd-phase-researcher` against the steering brief, requirements, state, and resolved canonical refs, with instructions to preserve `derived_constraints`, `future_awareness`, explicit non-decisions, and current posture rather than flattening them. Output is `*-RESEARCH.md`. Sources: `.codex/get-shit-done/workflows/research-phase.md:39-88`; `.codex/get-shit-done/workflows/plan-phase.md:306-415`.
- [e:c:i] `6. The planner is responsible for translating steering into executable, auditable plan contracts.` `plan-phase.md` tells the planner to treat `derived_constraints` and `future_awareness` as architectural guardrails, map each material future item to one preservation/validation/rationale bucket, record preserved seams in `future_preservation`, and emit executable PLAN artifacts with frontmatter, task bodies, verification, and must-haves suitable for `execute-phase`. Sources: `.codex/get-shit-done/workflows/plan-phase.md:694-758`; `.codex/get-shit-done/templates/phase-prompt.md:14-48,130-179`.
- [e:c:i] `7. Plan quality is gated twice before execution.` First, `gsd-plan-checker` reviews plans against `open_questions`, `derived_constraints`, and `future_awareness`, explicitly failing missing/generic `future_preservation` when context future-awareness is non-empty. Then `plan-phase.md` runs a requirement/context coverage gate that compares `requirements:` coverage and checks whether context-described features actually appear in plan objectives before recording planning completion in `STATE.md`. Sources: `.codex/get-shit-done/workflows/plan-phase.md:809-849,963-1023`.
- [e:c:i] `8. Auto-advance keeps the chain flat on purpose.` `discuss-phase.md` auto-advances into `gsd-plan-phase`; `plan-phase.md` auto-advances into `gsd-execute-phase --auto --no-transition`; both explain that the chain stays flat to avoid nested Task/session freezes. That makes the chain-control flags and return markers part of the workflow contract, even though they are not user artifacts. Sources: `.codex/get-shit-done/workflows/discuss-phase.md:1235-1272`; `.codex/get-shit-done/workflows/plan-phase.md:1028-1089`.
- [e:c:i] `9. Execution authority lives in execute-phase plus execute-plan, with plan metadata driving orchestration.` `execute-phase.md` groups work by `wave`, checks `files_modified` overlap before allowing parallelism, passes each executor the plan plus execution/summary/checkpoint references, uses worktree-specific protections when parallel, and keeps shared-doc updates under orchestrator ownership after merge-back. `execute-plan.md` is where per-task reading, deviations, checkpoints, per-task commits, summary creation, and plan-metadata commits are actually carried out. Sources: `.codex/get-shit-done/workflows/execute-phase.md:216-283,303-565`; `.codex/get-shit-done/workflows/execute-plan.md:139-152,177-220,256-337,384-467`.
- [e:c:i] `10. Execution completion is evidenced through SUMMARY and shared-state updates, not by trust in agent prose.` `execute-plan.md` creates `*-SUMMARY.md`, updates `STATE.md`, `ROADMAP.md`, and `REQUIREMENTS.md`, and commits the metadata set. `execute-phase.md` then spot-checks summary existence, recent commits, and self-check markers before it reports wave completion or continues. Sources: `.codex/get-shit-done/workflows/execute-plan.md:384-467`; `.codex/get-shit-done/workflows/execute-phase.md:441-463,567-596`.
- [e:c:i] `11. Goal-backward verification is the post-execution gate.` `execute-phase.md` spawns `gsd-verifier` with plans, summaries, requirements, and optionally context/research, and `gsd-verifier.md` explicitly says not to trust summaries, to verify roadmap success criteria plus plan must-haves against the actual codebase, and to emit `VERIFICATION.md` with `passed`, `gaps_found`, or `human_needed` status. Sources: `.codex/get-shit-done/workflows/execute-phase.md:954-1084`; `.codex/agents/gsd-verifier.md:13-30,68-152,154-220,702-717`.
- [e:c:i] `12. Human verification persists as artifacts rather than vanishing into chat.` If verification needs human judgment, `execute-phase.md` writes `*-HUMAN-UAT.md`; the standalone `verify-work.md` workflow likewise creates and maintains a UAT file derived from `SUMMARY.md` outputs so testing progress survives session loss and can feed later gap-planning. Sources: `.codex/get-shit-done/workflows/execute-phase.md:1000-1058`; `.codex/get-shit-done/workflows/verify-work.md:125-169,171-228`.

## Artifact Contract Map

- [e:c:i] `Shared canon/state docs` are part of the workflow chain, not ambient background. `discuss-phase.md` reads `PROJECT.md`, `REQUIREMENTS.md`, `STATE.md`, and optionally `LONG-ARC.md` to derive boundaries, prior decisions, and future-awareness; `plan-phase.md` and the verifier read roadmap/requirements for traceability; `execute-plan.md` and `execute-phase.md` update `STATE.md`, `ROADMAP.md`, and `REQUIREMENTS.md` as part of plan and phase completion. Sources: `.codex/get-shit-done/workflows/discuss-phase.md:322-376,470-487`; `.codex/get-shit-done/workflows/plan-phase.md:969-1023`; `.codex/get-shit-done/workflows/execute-plan.md:398-467`; `.codex/get-shit-done/workflows/execute-phase.md:551-565,1086-1114`.
- [e:c:i] `*-DISCUSS-CHECKPOINT.json` is the resumable steering checkpoint contract. It carries completed areas, pending areas, captured decisions, deferred ideas, and canonical refs so an interrupted discuss pass can resume without pretending the partial state is already canonical. It is explicitly deleted after `CONTEXT.md` is written. Sources: `.codex/get-shit-done/workflows/discuss-phase.md:893-927,1204-1208`.
- [e:c:i] `*-CONTEXT.md` is the canonical steering-brief contract. Required sections are `domain`, `decisions`, `canonical_refs`, `code_context`, `specifics`, `future_awareness`, and `deferred`; optional uncertainty-aware sections include `working_model`, `derived_constraints`, `open_questions`, and `epistemic_guardrails`. Downstream researcher and planner both treat it as the authoritative statement of locked decisions, guardrails, and preserved-open seams. Sources: `.codex/get-shit-done/templates/context.md:15-158`; `.codex/get-shit-done/workflows/discuss-phase.md:938-1117`; `.codex/get-shit-done/workflows/plan-phase.md:363-399,694-703`.
- [e:c:i] `*-DISCUSSION-LOG.md` is an audit-trail artifact, not a downstream steering artifact. `discuss-phase.md` says it is for human reference/software audits only and explicitly not for research, planning, or execution agents. Sources: `.codex/get-shit-done/workflows/discuss-phase.md:941-943,1159-1203`.
- [e:c:i] `*-RESEARCH.md` is the planning-research handoff artifact. It is produced from steering brief + requirements + state + canonical refs, and its contract is to investigate open questions and constraints in a way that helps planning rather than replacing planning. Nyquist validation strategy generation also depends on research being present. Sources: `.codex/get-shit-done/workflows/research-phase.md:39-88`; `.codex/get-shit-done/workflows/plan-phase.md:361-430`.
- [e:c:i] `*-PLAN.md` is the main planner-to-executor and planner-to-verifier contract. Its required frontmatter includes `phase`, `plan`, `type`, `wave`, `depends_on`, `files_modified`, `autonomous`, `requirements`, `must_haves`, and, when future-awareness exists, `future_preservation`. Its body contract includes executable tasks with `read_first`, concrete `action`, `acceptance_criteria`, plan-level verification, and success criteria. Sources: `.codex/get-shit-done/templates/phase-prompt.md:14-48,64-125,130-179`; `.codex/get-shit-done/references/agent-contracts.md:46-55`; `.codex/get-shit-done/workflows/plan-phase.md:709-758`.
- [e:c:i] `*-SUMMARY.md` is the executor-to-verifier and executor-to-later-UAT evidence artifact. It records substantive one-line outcome, frontmatter for dependency graph / tech stack / key files / decisions / completed requirements, per-task commits, deviations, and self-check status. `execute-phase.md` also uses it as the real completion signal for wave orchestration. Sources: `.codex/get-shit-done/templates/summary.md:7-48,52-148`; `.codex/get-shit-done/workflows/execute-plan.md:384-467`; `.codex/get-shit-done/references/agent-contracts.md:56-64,75-79`; `.codex/get-shit-done/workflows/execute-phase.md:441-463,567-576`.
- [e:c:i] `*-VERIFICATION.md` is the verifier's goal-backward decision artifact. It stores must-haves, gaps, deferred items, overrides, and the terminal status that `execute-phase.md` branches on (`passed`, `human_needed`, `gaps_found`). It is also the input surface for `plan-phase --gaps`. Sources: `.codex/agents/gsd-verifier.md:74-190,589-717`; `.codex/get-shit-done/workflows/execute-phase.md:994-1084`.
- [e:c:i] `*-HUMAN-UAT.md` and `*-UAT.md` are persistent human-testing contracts. `execute-phase.md` writes `HUMAN-UAT.md` when verifier status is `human_needed`; `verify-work.md` creates/updates UAT files from `SUMMARY.md` deliverables so manual testing is durable, resumable, and gap-feedable into later planning. Sources: `.codex/get-shit-done/workflows/execute-phase.md:1000-1058`; `.codex/get-shit-done/workflows/verify-work.md:1-5,125-169,171-252`.
- [e:c:i] `templates/config.json` is part of the workflow-chain contract surface because it names the knobs the workflows expect to read and react to: `workflow.research`, `plan_check`, `verifier`, `auto_advance`, `discuss_mode`, gate confirmations, parallelization, and safety toggles. In this lane it should be treated as the stock/default contract vocabulary, not as proof of effective repo-local runtime truth. Sources: `.codex/get-shit-done/templates/config.json:1-48`; `.codex/get-shit-done/workflows/discuss-phase.md:190-200,1238-1249`; `.codex/get-shit-done/workflows/plan-phase.md:34-41,225-228,1039-1043`; `.codex/get-shit-done/workflows/execute-phase.md:77-89,1191-1198`.

## Preserve-Only And Future-Awareness Seams

- [e:c:i] `Future-awareness is captured upstream and is explicitly scope-constrained.` `discuss-phase.md` derives `Protected Seams`, `Explicit Non-Decisions`, `Current Posture`, and `Future Shape Notes` from roadmap/canon/downstream context while warning that this is not a license to import future scope into the current phase. Sources: `.codex/get-shit-done/workflows/discuss-phase.md:478-487,1076-1093`; `.codex/get-shit-done/templates/context.md:126-152`.
- [e:c:i] `Canonical refs are the preserve-only seam for doctrinal/source continuity.` The workflow insists on full relative paths, keeps the list mandatory in `CONTEXT.md`, and resolves it into downstream file reads so later stages do not silently re-derive or replace the governing inputs. Sources: `.codex/get-shit-done/workflows/discuss-phase.md:468-476,1031-1051`; `.codex/get-shit-done/workflows/plan-phase.md:291-304`.
- [e:c:i] `Explicit non-decisions and open questions are meant to survive into research/planning rather than being hand-waved away.` The researcher is told to treat explicit non-decisions as open by default and the planner is told not to collapse them silently; unresolved open questions must become research dependencies, validation work, or early tasks. Sources: `.codex/get-shit-done/workflows/plan-phase.md:383-391,695-703`; `.codex/get-shit-done/workflows/research-phase.md:71-80`.
- [e:c:i] `Future-awareness only becomes execution-safe when it is translated into auditable plan metadata.` `plan-phase.md` requires every material future-awareness item to map to a preserved seam, sequencing choice, validation task, or explicit non-action rationale, and `gsd-plan-checker` is instructed to fail missing or generic `future_preservation` data. Sources: `.codex/get-shit-done/workflows/plan-phase.md:698-703,709-716,840-845`; `.codex/get-shit-done/templates/phase-prompt.md:25-34,143-149,162-165`.
- [e:c:i] `Human uncertainty is also preserved as artifacts.` Verifier `human_needed` items become `HUMAN-UAT.md`, and `verify-work.md` persists manual testing state in `UAT.md`; unresolved failures become explicit gap-closure planning inputs rather than chat-only residue. Sources: `.codex/get-shit-done/workflows/execute-phase.md:1000-1084`; `.codex/get-shit-done/workflows/verify-work.md:1-5,171-228`.
- [e:c:i] `Artifact-class boundaries are explicit inside discuss-phase.` `DISCUSS-CHECKPOINT.json` is resumable partial state, `CONTEXT.md` is canonical steering, and `DISCUSSION-LOG.md` is audit trail only. That separation is load-bearing because collapsing those classes would make later planning or audit readers consume the wrong artifact for the wrong purpose. Sources: `.codex/get-shit-done/workflows/discuss-phase.md:919-927,941-943,1204-1214`.

## Narrow but Structurally Decisive Surfaces

- [e:c:i] `Exploratory no-context gate` is narrow but decisive. In exploratory mode, absent `CONTEXT.md` is a hard stop unless the operator explicitly accepts reduced guarantees with `--allow-no-context`. That one gate decides whether future-aware planning is mandatory doctrine or optional advice. Sources: `.codex/get-shit-done/workflows/plan-phase.md:223-252`.
- [e:c:i] `Canonical-refs resolution` is narrow but decisive. The planner/researcher/checker prompts are supposed to read the exact files cited in `CONTEXT.md`; if that resolution is sloppy, the chain silently detaches from its declared sources of truth. Sources: `.codex/get-shit-done/workflows/plan-phase.md:291-304,370-375,827-833`.
- [e:c:i] `PLAN frontmatter fields` are narrow but decisive because they drive downstream grouping, safety, traceability, and verification: `wave`, `depends_on`, `files_modified`, `requirements`, `future_preservation`, and `must_haves` are not decorative metadata. Sources: `.codex/get-shit-done/templates/phase-prompt.md:14-34,130-149`; `.codex/get-shit-done/workflows/execute-phase.md:223-283`; `.codex/agents/gsd-verifier.md:111-152`.
- [e:c:i] `SUMMARY-based completion detection` is narrow but decisive. `execute-phase.md` intentionally treats `SUMMARY.md` + commit evidence + self-check as the practical completion contract, even though the executor nominally reports `## PLAN COMPLETE`. Sources: `.codex/get-shit-done/references/agent-contracts.md:13-18,67-79`; `.codex/get-shit-done/workflows/execute-phase.md:441-463,567-576`.
- [e:c:i] `Single-writer ownership of shared planning docs during worktree execution` is narrow but decisive. Executors in worktree mode are told not to update `STATE.md` or `ROADMAP.md`; the orchestrator restores/merges and then applies shared updates once after the wave. That seam determines whether parallel execution preserves or corrupts the shared planning state. Sources: `.codex/get-shit-done/workflows/execute-phase.md:340-343,475-565`.
- [e:c:i] `Verification status triage` is narrow but decisive. The `passed` / `human_needed` / `gaps_found` split controls whether the workflow closes the phase, persists human testing, or opens a gap-closure loop via `plan-phase --gaps`. Sources: `.codex/get-shit-done/workflows/execute-phase.md:989-1084`; `.codex/agents/gsd-verifier.md:534-717`.

- [p:r:i] Later audit should treat `CONTEXT.md -> RESEARCH.md -> PLAN.md -> SUMMARY.md -> VERIFICATION/UAT` as the main contract spine and test whether each handoff preserves what the previous stage declared load-bearing, especially `canonical_refs`, `open_questions`, `future_awareness`, `requirements`, and `must_haves`. - [p:r:i] The later audit should sample the real branch points, not only the happy path:
  - normal discuss-driven planning
  - PRD express context generation
  - exploratory hard-stop versus `--allow-no-context`
  - auto-advance flat chain
  - worktree parallel execution versus sequential execution
  Sources: `.codex/get-shit-done/workflows/discuss-phase.md:1235-1272`; `.codex/get-shit-done/workflows/plan-phase.md:92-252,1028-1089`; `.codex/get-shit-done/workflows/execute-phase.md:303-565`.
