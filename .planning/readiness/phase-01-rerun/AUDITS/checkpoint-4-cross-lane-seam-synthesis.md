Trigger: if the converged synthesis agrees that epistemic richness is still being flattened after research. Likely owner: `doc-level doctrine` plus `workflow-protocol`.

Trigger: only if Checkpoint 5 touches reinstall/materialization surfaces directly or if Checkpoint 6 later finds rerun trust still depends on reinstall truth. Likely owner: `machinery-owned`.
- [p:r:i] `Bounded launch-truth capture`: add a durable, reviewable capture step around effective spawn settings if manual verification continues to drift or disappear in practice. Trigger: if the converged synthesis treats current protocol-only launch checking as too fragile for later audit. Likely owner: `workflow-protocol` with a possible `machinery-owned` assist.

## Synthesis Handoff

- [e:r:i] The evidence set is strong enough for a real Checkpoint 4 verdict. The main conclusion already visible from the seams is not “everything reduces to docs” and not “the harness needs a giant redesign.” It is that the repo has meaningful excellence-supporting machinery and protocol, but two bounded areas now look too real to dismiss:
  - runtime-authoritative worker truth for the phase-critical chain
  - closure and review pressure that is still biased toward acceptable completion
- [e:r:i] By contrast, broader install pinning, provenance cleanup, and portability hardening now read as real quality opportunities that may become Checkpoint 5 scope only if the actual follow-through reaches reinstall/materialization surfaces. Otherwise they should stay explicit follow-on hardening rather than silently inflating the pre-rerun checkpoint.
- [e:r:i] The converged synthesis should therefore test a narrow but serious possibility: a bounded Checkpoint 5 is justified, but only if it stays targeted to clean ownership stories instead of reopening omnibus harness redesign.
