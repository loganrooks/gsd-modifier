## Active Agent-Role Contract Map

- [e:c:i] `Discuss-stage role`: the load-bearing contract is mostly workflow-owned, not subagent-owned. `discuss-phase.md` produces the steering brief itself; the only extra discuss-role agent in this lane is `gsd-advisor-researcher`, which is optional and limited to gray-area comparison tables. Sources: `.codex/get-shit-done/workflows/discuss-phase.md:1-29,503-530`; `.codex/agents/gsd-advisor-researcher.md:1-83`.
- [e:c:i] `gsd-phase-researcher` is the research-to-planning bridge. It must read mandatory prompt files first, treat AGENTS directives as planner-relevant constraints, treat CONTEXT decisions/deferred ideas as hard scope boundaries, prefer current tooling/doc sources over training memory, and return `RESEARCH.md` with structured completion or blocked markers. Sources: `.codex/agents/gsd-phase-researcher.md:18-34,36-51,53-80,84-199,470-480,661-714`; `.codex/get-shit-done/workflows/plan-phase.md:355-415`.
- [e:c:i] `gsd-planner` is the highest-consequence role contract in the phase chain. It must honor locked decisions, forbid silent scope reduction, split phases instead of simplifying user decisions, build executable prompt-plans with automated verification, and return completion markers that unlock the checker and later executor. Sources: `.codex/agents/gsd-planner.md:24-35,44-127,171-257,1197-1265`; `.codex/get-shit-done/workflows/plan-phase.md:654-775`.
- [e:c:i] `gsd-plan-checker` is the pre-execution quality gate. Its contract is not just structural linting; it verifies requirement coverage, task completeness, dependencies, key links, context compliance, AGENTS compliance, research resolution, and cross-plan data-contract conflicts before execution burns context. Sources: `.codex/agents/gsd-plan-checker.md:13-31,34-39,55-89,100-258,454-527,541-870`; `.codex/get-shit-done/workflows/plan-phase.md:809-869`.
- [e:c:i] `gsd-executor` is the implementation-and-state-transition role. It treats AGENTS directives as hard constraints during execution, auto-fixes correctness/security/blocking issues inside bounded deviation rules, stops at checkpoints, updates state/roadmap/requirements after SUMMARY, and returns `## PLAN COMPLETE`. - [e:c:i] `gsd-verifier` is the post-execution truth gate. It explicitly distrusts SUMMARY claims, treats roadmap success criteria as non-negotiable, applies the anti-stub/wiring doctrine, writes `VERIFICATION.md` frontmatter suitable for `--gaps`, and returns a non-committing escalation verdict rather than mutating repo state itself.
