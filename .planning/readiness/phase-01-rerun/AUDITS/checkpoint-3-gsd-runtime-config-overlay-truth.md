## Config Surface Map

- [e:c:i] `Normalized config truth` lives in `loadConfig()` inside `core.cjs`, not in `templates/config.json`. `loadConfig()` reads `.planning/config.json`, migrates deprecated keys, syncs `sub_repos`, warns on unknown top-level keys, normalizes `parallelization`, auto-detects `commit_docs`, and returns the normalized config object that init/state/resolve-model/commit code paths actually consume. Sources: `.codex/get-shit-done/bin/lib/core.cjs:245-399`; `.codex/get-shit-done/bin/lib/state.cjs:27-47`; `.codex/get-shit-done/bin/lib/init.cjs:43-48,178-240,448-478`.
- [e:c:i] `config-new-project` also bypasses `templates/config.json`. It materializes `.planning/config.json` from `CONFIG_DEFAULTS`, optional `~/.gsd/defaults.json`, and explicit user choices; the template file is not read in that path. Sources: `.codex/get-shit-done/bin/lib/config.cjs:76-90,122-186,198-231`.
- [e:r:i] `templates/config.json` is therefore a baseline/document artifact, not an effective runtime loader. Repo-wide search found no runtime code reference to `templates/config.json`; the only repo mention outside the file itself is the overlay README's update list. Basis: direct repo search, grounded by `.codex/get-shit-done/templates/config.json:1-48`; `tooling/portable-gsd/README.md:42-49`.
- [e:c:i] `Project overrides that materially change effective posture` are concentrated in `.planning/config.json`: `model_profile: "quality"`, `parallelization: true`, `workflow.auto_advance: true`, `workflow.node_repair: true`, `workflow.ui_phase: true`, `workflow.ui_safety_gate: true`, `workflow.code_review: true`, `model_overrides` for four core roles to `gpt-5.4`, `resolve_model_ids: "omit"`, plus `mode: "yolo"` and `granularity: "fine"`. Sources: `.planning/config.json:1-48`.
- [e:c+r:i] `Not every stored key is part of normalized runtime config`: `mode` and `granularity` are valid config keys and present in `.planning/config.json`, but `loadConfig()` does not return either field in the normalized config object. That means `config-get mode` / `config-get granularity` can return real values from raw JSON while `state load` and init outputs omit them. Sources: `.codex/get-shit-done/bin/lib/config.cjs:14-24`; `.planning/config.json:1-48`; `.codex/get-shit-done/bin/lib/core.cjs:331-366`; `.codex/get-shit-done/bin/lib/state.cjs:27-47`.
- [e:c+r:i] `Config read surface and config write surface are not the same`. `config-set` enforces `VALID_CONFIG_KEYS`, but `config-get` simply traverses the raw JSON path without validating that the key is part of the supported schema. This lets workflow markdown honor keys that the supported setter refuses to write. Sources: `.codex/get-shit-done/bin/lib/config.cjs:14-39,335-397`.
- [e:c+i] Concrete examples of that asymmetry already exist:
  - `workflow.max_discuss_passes` is read directly in `discuss-phase.md` with a fallback of `3`, but it is not in `VALID_CONFIG_KEYS` or `loadConfig()`. Sources: `tooling/portable-gsd/overlay/get-shit-done/workflows/discuss-phase.md:805-808`; `.codex/get-shit-done/bin/lib/config.cjs:14-39`; `.codex/get-shit-done/bin/lib/core.cjs:331-366`.
  - `workflow.security_enforcement`, `workflow.security_asvs_level`, and `workflow.security_block_on` are read directly in `plan-phase.md` with shell fallbacks, but they are likewise absent from `VALID_CONFIG_KEYS` and the normalized return object. Sources: `.codex/get-shit-done/workflows/plan-phase.md:446-455`; `.codex/get-shit-done/bin/lib/config.cjs:14-39`; `.codex/get-shit-done/bin/lib/core.cjs:331-366`.
- [e:c+i] `Parallelization` is polymorphic across surfaces. The template config stores an object under `parallelization.enabled`, the project file stores a bare boolean, and `loadConfig()` normalizes either form to one boolean. Later audit should not mistake file-shape differences here for behavioral differences without checking the loader path. Sources: `.codex/get-shit-done/templates/config.json:21-28`; `.planning/config.json:4`; `.codex/get-shit-done/bin/lib/core.cjs:324-329`; `.codex/get-shit-done/references/planning-config.md:331-345`.
- [e:c+i] `commit_docs` has behavior beyond raw file value. `loadConfig()` respects explicit config, but if no explicit value exists and `.planning/` is gitignored it auto-resolves to `false`; commit commands then enforce that normalized value. Sources: `.codex/get-shit-done/bin/lib/core.cjs:333-341`; `.codex/get-shit-done/references/planning-config.md:333-345`; `.codex/get-shit-done/bin/lib/commands.cjs:262-275`.
