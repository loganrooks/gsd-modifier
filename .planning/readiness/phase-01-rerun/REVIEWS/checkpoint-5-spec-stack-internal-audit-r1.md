## What Must Change Before Implementation

- Revise the implementation spec so every touched `.codex/` runtime file has an explicitly paired tracked overlay/materialization surface where one exists. This must be written as required implementation scope, not left as an implicit “if needed” memory.
- Expand the named change set beyond the four workflows to include the runtime-authoritative prompt surfaces that currently consume CONTEXT and RESEARCH semantics: at minimum the tracked researcher, planner, checker, and executor prompt overlays that the portable install path projects into `.codex/`.
- Define one research disposition contract and name every surface that must carry it: orchestrator workflow, RESEARCH template, researcher return contract, checker logic, and any contract reference file that defines accepted return markers.
- Define one debt-carrying completion contract and name every surface that must carry it: execute workflow, executor checkpoint behavior, and shared checkpoint/template/reference surfaces that currently normalize `approved` as ordinary completion.
- After revising the spec, review the revised spec again before treating any workflow or wrapper patch set as checkpoint-moving evidence.

## Propagation Consequences

- Accepting the spec revision will likely require touching both live runtime files and tracked overlay truth for the workflow lane: `discuss-phase.md`, `research-phase.md`, `plan-phase.md`, `execute-phase.md`, plus any overlay counterparts that the portable installer projects into `.codex/`.
- It will also likely require explicit updates to shared contract surfaces, not just workflow prose: `context.md`, `research.md`, `phase-prompt.md`, `checkpoints.md`, `ui-brand.md`, and `agent-contracts.md`, plus the tracked overlay agents that consume those contracts.
- Review criteria for the later Checkpoint 5 reread must test reinstallability from overlay truth, not only “does the current local `.codex` copy look right right now.”
- Wrapper alignment can still remain secondary, but only after the revised spec names the workflow, template, reference, and agent surfaces whose semantics the wrappers are supposed to mirror.

## Change Summary

[d:c+r:i] The candidate stack is directionally correct but still under-scoped. The next move is not to start patching the four workflow files; it is to revise the implementation spec so it explicitly owns install-truth materialization and the shared agent/template/reference surfaces that those workflow changes depend on. Once that revision exists, the checkpoint can proceed as a bounded follow-through rather than as another partial bundle that later review has to reopen.
