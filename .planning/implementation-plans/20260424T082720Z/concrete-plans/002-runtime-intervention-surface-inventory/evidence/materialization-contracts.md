# Materialization Contracts And Verification Hooks

## Summary

The materialization path is explicit and mutating. `scripts/setup-portable-gsd.sh` is a Codex-only wrapper that delegates to `scripts/setup-portable-gsd-runtime.sh --runtime codex` (`scripts/setup-portable-gsd.sh:4-6`). The runtime setup script accepts `codex`, `claude`, or `both`, expands `both` into both supported runtime passes, and rejects unsupported runtime names (`scripts/setup-portable-gsd-runtime.sh:9-12`, `scripts/setup-portable-gsd-runtime.sh:40-55`). Each runtime pass installs upstream local GSD, captures pristine overwrite copies, validates the overlay manifest, applies overlay entries, applies repo-local defaults, and verifies the materialized runtime (`scripts/setup-portable-gsd-runtime.sh:67-112`).

The source contract is the schema-3 overlay manifest plus the compatibility declaration. The manifest gives each logical carrier a `capability_id`, `parity_tier`, and runtime-specific `materializers` with `mode`, `target`, and `source` fields (`tooling/portable-gsd/overlay/OVERLAY-MANIFEST.json:1-18`, `tooling/portable-gsd/overlay/OVERLAY-MANIFEST.json:167-176`). The compatibility declaration defines active `codex-core`, `claude-core`, and `dual-runtime-core` posture while warning that broader host compatibility still depends on the manual synthetic host matrix (`harness_modifier/compatibility/declaration.json:11-29`, `harness_modifier/compatibility/declaration.json:44-65`).

Inference: future runtime-surface changes should be sorted by whether they change source declarations only, materialized runtime content, repo-self CI proof, or broader-host claims. That inference follows from the split between source-only validation in `validate-manifest --source-only`, materialized verification in `verify-materialized`, bootstrap CI running `setup-portable-gsd-runtime.sh --runtime both`, and the separate host-matrix command (`harness_modifier/contract/portable_gsd_contract.py:60-70`, `harness_modifier/contract/portable_gsd_contract.py:91-98`, `scripts/ci/check-bootstrap.sh:9-18`, `harness_modifier/closure/host_exercise_matrix.py:144-170`).

## Materialization Path Map

1. Wrapper entry: `scripts/setup-portable-gsd.sh` resolves repo root and executes `scripts/setup-portable-gsd-runtime.sh --runtime codex`, so it is a Codex profile shortcut rather than the full dual-runtime installer (`scripts/setup-portable-gsd.sh:4-6`).

2. Runtime selection: `scripts/setup-portable-gsd-runtime.sh` requires `--runtime codex|claude|both`, maps `both` to `codex` and `claude`, and rejects unsupported runtime names (`scripts/setup-portable-gsd-runtime.sh:34-55`).

3. Upstream baseline install: each selected runtime runs `GSD_ALLOW_OFF_PATH=1 npx get-shit-done-cc --<runtime> --local`; nonzero exit codes other than `2` abort, while Codex exit code `2` can be recovered through repo-local SDK runtime verification (`scripts/setup-portable-gsd-runtime.sh:67-85`).

4. Pristine overwrite capture: after upstream install, the runtime script calls `portable_gsd_contract.py capture-pristine-overwrites <repo> --runtime <runtime> --strict` (`scripts/setup-portable-gsd-runtime.sh:87-90`). That helper copies overwrite-mode live files into `<runtime-root>/gsd-local-patches/` and writes `backup-meta.json` listing copied files (`harness_modifier/contract/portable_gsd_contract.py:617-675`).

5. Source manifest validation: the runtime script calls `validate-manifest <repo> --runtime <runtime> --strict` before applying overlay content (`scripts/setup-portable-gsd-runtime.sh:91-94`). The checker loads schema-3 entries, flattens materializers per runtime, rejects duplicate runtime targets, and requires `core_required` / `core_adapted` entries to declare all supported runtimes (`harness_modifier/contract/portable_gsd_contract.py:293-341`, `harness_modifier/contract/portable_gsd_contract.py:534-553`).

6. Overlay application: the runtime script calls `apply-overlay`, passing the selected compact prompt file (`scripts/setup-portable-gsd-runtime.sh:95-100`). The helper renders `__PROJECT_ROOT__` and `__COMPACT_PROMPT_FILE__` placeholders before writing each manifest target into the runtime root (`harness_modifier/contract/portable_gsd_contract.py:175-176`, `harness_modifier/contract/portable_gsd_contract.py:678-689`).

7. Repo-local defaults: the runtime script calls `apply-reasoning-defaults` after overlay application (`scripts/setup-portable-gsd-runtime.sh:102-105`). That helper is Codex-only; it sets `.codex/config.toml` to `model_reasoning_effort = "xhigh"` and applies per-agent reasoning defaults from `QUALITY_REASONING` (`harness_modifier/contract/portable_gsd_contract.py:33-51`, `harness_modifier/contract/portable_gsd_contract.py:692-716`).

8. Post-materialization verification: the runtime script calls `verify-materialized <repo> --runtime <runtime> --compact-prompt-file <file> --strict` (`scripts/setup-portable-gsd-runtime.sh:107-112`). The checker verifies live target presence, backup copies for overwrite entries, content equality after template rendering and reasoning-default normalization, overlay schema alignment, and runtime-specific reference scan results (`harness_modifier/contract/portable_gsd_contract.py:718-829`).

9. Runtime adapters: Codex and Claude adapters expose matching methods for install, pristine capture, overlay application, defaults, and materialized verification, but target different runtime roots and profiles (`harness_modifier/contract/runtime_adapters/codex.py:13-64`, `harness_modifier/contract/runtime_adapters/claude.py:13-64`). The registry declares only `codex` and `claude` as supported runtime adapters (`harness_modifier/contract/runtime_adapters/registry.py:9-26`).

## Contract Checker Inventory

- `portable_gsd_contract.py validate-manifest`: source or source-plus-backup contract validation. It validates manifest shape, overlay coverage, source file existence, modes, external source entries, and backup-meta consistency when backup metadata is required (`harness_modifier/contract/portable_gsd_contract.py:60-70`, `harness_modifier/contract/portable_gsd_contract.py:475-601`). Source verification: use `--source-only` when runtime trees or backup metadata should not be required (`harness_modifier/contract/portable_gsd_contract.py:66-70`, `harness_modifier/contract/portable_gsd_contract.py:858-878`).

- `portable_gsd_contract.py capture-pristine-overwrites`: materialization preparation. It reads current live runtime files and writes pristine backup copies plus `gsd-local-patches/backup-meta.json` for overwrite-mode entries (`harness_modifier/contract/portable_gsd_contract.py:617-675`). Materialized-runtime verification depends on this backup metadata for overwrite entries (`harness_modifier/contract/portable_gsd_contract.py:771-783`).

- `portable_gsd_contract.py apply-overlay`: materialization writer. It renders overlay templates and writes manifest targets into `.codex` or `.claude` according to the runtime adapter root (`harness_modifier/contract/portable_gsd_contract.py:678-689`, `harness_modifier/compatibility/declaration.json:11-29`).

- `portable_gsd_contract.py apply-reasoning-defaults`: Codex-only runtime default writer. It mutates `.codex/config.toml` and `.codex/agents/*.toml` reasoning settings after overlay application (`harness_modifier/contract/portable_gsd_contract.py:169-172`, `harness_modifier/contract/portable_gsd_contract.py:692-716`).

- `portable_gsd_contract.py verify-materialized`: materialized-runtime coherence checker. It composes manifest validation with live target checks, backup-copy checks, normalized content checks, compatibility declaration checks, and runtime-specific reference scanning (`harness_modifier/contract/portable_gsd_contract.py:718-829`, `harness_modifier/contract/portable_gsd_contract.py:897-910`).

- `runtime_visibility.py`: read-only final runtime truth report for selected surface families. It compares overlay specs, live runtime files, upstream manifest entries, backup metadata, install mutation targets, template-rendered overlay content, and parity state across selected runtimes (`harness_modifier/contract/runtime_visibility.py:53-59`, `harness_modifier/contract/runtime_visibility.py:316-430`, `harness_modifier/contract/runtime_visibility.py:433-552`). Inference: this is a materialized-runtime observation tool, not a source-only manifest gate, because it reads live runtime roots and classifies live-only, overlay-covered, backup, and install-mutated surfaces (`harness_modifier/contract/runtime_visibility.py:316-430`).

- `manifest_install_coherence.py`: snapshot comparison gate. It requires a captured runtime snapshot, compares updater manifest truth, carried-subset metadata, and current selected runtime scope, and evaluates gates including snapshot scope, clean boundary, unknown drift, obsolete residue, and dual-runtime conflict status (`harness_modifier/contract/manifest_install_coherence.py:20-42`, `harness_modifier/contract/manifest_install_coherence.py:170-242`, `harness_modifier/contract/manifest_install_coherence.py:245-392`). Inference: use it when a durable snapshot exists and the question is whether runtime visibility, updater manifest semantics, and carried-subset semantics still agree (`harness_modifier/contract/manifest_install_coherence.py:338-366`).

- `harness_canary.py`: repo-self canary. It checks runtime version anchors, manifest validation, post-materialization coherence, Codex reasoning defaults, high-stakes Codex agent reasoning defaults, uplift compatibility anchor state, and dual-runtime core alignment (`harness_modifier/contract/harness_canary.py:79-139`, `harness_modifier/contract/harness_canary.py:142-207`, `harness_modifier/contract/harness_canary.py:209-239`, `harness_modifier/contract/harness_canary.py:275-326`). Its `--strict` mode exits nonzero when issue checks are present (`harness_modifier/contract/harness_canary.py:371-379`).

## CI And Host-Matrix Gates

- Deterministic CI is source-focused. It compiles Python files, shell-checks scripts with `bash -n`, runs targeted unit tests, validates the overlay manifest with `--source-only --strict`, verifies archived origin-audit checksums, and runs `git diff --check` (`scripts/ci/check-deterministic.sh:9-27`). Inference: source-only runtime-surface changes should at least pass this gate when they affect overlay manifest shape, contract code, adapters, CI scripts, or tests (`scripts/ci/check-deterministic.sh:9-27`).

- Bootstrap CI is materialization-focused. It runs `./scripts/setup-portable-gsd-runtime.sh --runtime both`, all `tooling/codex/tests`, `harness_canary.py report . --all-supported --strict`, `validate-manifest . --all-supported --strict`, `verify-materialized . --all-supported --strict`, `audit_refmap.py verify .`, and `git diff --check` (`scripts/ci/check-bootstrap.sh:9-18`). Inference: any change that should alter live `.codex` or `.claude` runtime behavior requires bootstrap CI or equivalent materialized-runtime proof (`scripts/ci/check-bootstrap.sh:9-18`).

- The synthetic host matrix is the broader-host proof gate, not a silent widening of support language. The compatibility declaration says repo-self dual-runtime proof is in bootstrap and CI, while broader host-language changes rely on the manual synthetic host matrix (`harness_modifier/compatibility/declaration.json:55-65`, `harness_modifier/compatibility/declaration.json:68-72`). The matrix has Codex and dual-runtime scenarios for read-side, aligned, and drift/conflict hosts with expected dispositions and parity states (`harness_modifier/closure/host_exercise_matrix.py:39-139`).

- Host-matrix materialization is synthetic and isolated. The matrix renders overlay entries into staged host runtime roots, writes backup metadata for overwrite entries, writes runtime basis files, initializes a temporary git repo, and writes `matrix-summary.json` under the requested output directory (`harness_modifier/closure/host_exercise_matrix.py:251-335`, `harness_modifier/closure/host_exercise_matrix.py:465-532`). Inference: run the host matrix before changing claims about broader host compatibility, not for every source-only manifest edit (`harness_modifier/compatibility/declaration.json:55-65`, `harness_modifier/closure/host_exercise_matrix.py:144-170`).

## Unknowns And Risks

- This Agent C pass maps contracts and verification hooks; it does not certify a freshly materialized runtime state. Fresh certification requires the mutating bootstrap path or equivalent setup plus `verify-materialized --all-supported --strict` (`scripts/setup-portable-gsd-runtime.sh:87-112`, `harness_modifier/contract/portable_gsd_contract.py:897-910`).

- Source-only validation can prove manifest shape and source coverage without backup metadata, but it intentionally does not prove live runtime targets or backup copies (`harness_modifier/contract/portable_gsd_contract.py:60-70`, `harness_modifier/contract/portable_gsd_contract.py:530-571`). Inference: a source-only green result should not be described as runtime behavior being installed.

- The overlay manifest contains runtime-specific carriers, shared core carriers, and adapted core carriers; parity means equivalent modifier-owned outcomes rather than identical runtime wrappers (`harness_modifier/compatibility/declaration.json:31-43`, `tooling/portable-gsd/overlay/OVERLAY-MANIFEST.json:959-973`). Inference: reviewers should inspect adapted entrypoints semantically, not only compare file paths.

- Runtime-specific reference scanning is Codex-focused and explicitly scoped to live `.codex` `.md`/`.toml` files with declared baseline rules (`harness_modifier/compatibility/declaration.json:73-109`, `harness_modifier/contract/portable_gsd_contract.py:427-472`). Inference: Claude parity risks may need other probes when the issue is operator-facing rather than manifest/materialization equality (`harness_modifier/contract/runtime_adapters/claude.py:66-72`).

- Host-matrix output is synthetic and writes fixtures/artifacts under the requested output directory and staging root (`harness_modifier/closure/host_exercise_matrix.py:193-195`, `harness_modifier/closure/host_exercise_matrix.py:465-532`). Inference: use it deliberately as a release-readiness or support-language gate, not as a hidden side effect of ordinary evidence collection.
