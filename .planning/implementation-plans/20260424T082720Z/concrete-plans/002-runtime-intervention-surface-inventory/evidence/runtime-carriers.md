## Runtime-specific surfaces

- Codex-specific maintained carriers include `tooling/portable-gsd/overlay/config.toml`, Codex `.toml` agent registry files, Codex skill wrappers, and compact prompt files. The manifest marks `config.toml`, agent `.toml` files, skills, and compact prompts as `runtime_specific` with Codex materializers (`tooling/portable-gsd/overlay/OVERLAY-MANIFEST.json:20-30`, `tooling/portable-gsd/overlay/OVERLAY-MANIFEST.json:167-177`, `tooling/portable-gsd/overlay/OVERLAY-MANIFEST.json:882-958`, `tooling/portable-gsd/overlay/OVERLAY-MANIFEST.json:1095-1116`).
- Codex runtime configuration carries current model/default settings and registered agent config file paths under `__PROJECT_ROOT__/.codex/agents/*.toml` (`tooling/portable-gsd/overlay/config.toml:1-10`, `tooling/portable-gsd/overlay/config.toml:12-106`).
- Claude-specific maintained carriers are command wrappers and runtime settings/hook family declarations rather than Codex TOML/skill wrappers. The install profile names Claude command wrappers and `settings.json` / hook carriers as runtime-specific examples, while the sampled specialist command wrapper targets `.claude/get-shit-done/workflows/...` (`docs/install-profiles.md:31-42`, `harness_modifier/overlay/commands/gsd/propagation-review.md:17-27`).
- Core-adapted specialist entrypoints map one capability to different runtime surfaces: Codex receives `skills/gsd-propagation-review/SKILL.md`, while Claude receives `commands/gsd/propagation-review.md` (`tooling/portable-gsd/overlay/OVERLAY-MANIFEST.json:959-973`).
- Inference: runtime-specific divergence is an allowed design boundary, not automatically a parity failure, because the compatibility declaration says runtime-specific carriers may vary and do not fail parity by themselves (`harness_modifier/compatibility/declaration.json:31-43`).
