# Template And Body Semantics

## Observed Facts

- Installed upstream template source: `/home/rookslog/.npm/_npx/9785a834b31d581d/node_modules/get-shit-done-cc/get-shit-done/templates/claude-md.md`.
- Installed upstream template title is `CLAUDE.md Template`.
- Installed upstream says the file is project-root `CLAUDE.md`, auto-generated by `gsd-tools generate-claude-md`.
- Installed upstream sections are marker-bounded:
  - `project`
  - `stack`
  - `conventions`
  - `architecture`
  - `skills`
  - `workflow`
  - `profile`
- Installed upstream fallback and workflow text uses Claude-native slash commands, including `/gsd-new-project`, `/gsd-quick`, `/gsd-debug`, `/gsd-execute-phase`, and `/gsd-profile-user`.
- Materialized Codex template at `.codex/get-shit-done/templates/claude-md.md` has been rewritten locally to `AGENTS.md Template`.
- The materialized Codex template uses Codex-style `$gsd-*` commands in the initialization, workflow, and profile text.
- Materialized Claude template at `.claude/get-shit-done/templates/claude-md.md` remains `CLAUDE.md Template` with slash-command text.
- Both materialized CJS writers use the same `profile-output.cjs` function shape: create the managed sections if the output file is absent, refresh existing GSD marker sections if present, append missing marker sections to existing files, and preserve non-GSD surrounding content.
- The repo source overlay does not currently carry `get-shit-done/templates/claude-md.md`, `get-shit-done/bin/gsd-tools.cjs`, or `get-shit-done/bin/lib/profile-output.cjs` as source-owned overlay entries.

## Body Classification

| Body surface | Classification | Basis |
| --- | --- | --- |
| Installed upstream `claude-md.md` | Claude-specific | Names `CLAUDE.md`, says generated file is for Claude, and uses slash-command examples. |
| Materialized `.claude` template/body | Claude-specific | Keeps `CLAUDE.md` title, Claude wording, and slash commands. |
| Materialized `.codex` template/body | Mostly runtime-neutral for `AGENTS.md` with Codex command spelling | Names `AGENTS.md`, uses `$gsd-*`, and changes fallback wording from Claude-only to agent-oriented wording in places. |
| Current SDK JSON sections | Not a file body | Returns JSON and does not manage marker sections or profile placeholder. |

## Inferences

- Using the installed upstream or materialized Claude CJS body to write `AGENTS.md` would be semantically misleading because the body still describes a Claude-oriented instruction file.
- Using the materialized Codex CJS writer from a shared workflow would produce a more honest `AGENTS.md` body, but it would make a shared initialization workflow depend on a Codex runtime root.
- The right source-level body contract is a runtime-neutral `AGENTS.md` body owned by this repo and materialized into both supported runtime roots.
- The existing marker-section model is a good conflict/update policy to preserve because it avoids overwriting user content outside GSD markers.
