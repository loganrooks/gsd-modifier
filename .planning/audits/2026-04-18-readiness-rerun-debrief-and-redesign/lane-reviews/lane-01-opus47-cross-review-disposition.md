## Overall Disposition

- [d:r:i] Accept the review as a strong challenge artifact, not as sovereign doctrine.
- [d:r:i] Accept the core pressure that the current setup is still too narrow in at least three ways:
  - it may be inheriting too much from the `04-17` bridge audit
  - it underweights runtime / harness code as first-class evidence
  - it may be assuming a readiness-rerun unit too quickly
- [d:r:i] Reject the strongest version of the review's appeal to strict falsifiability as the governing standard for framing claims.

## What Is Accepted

### 1. Runtime / Harness Code Must Become First-Class Evidence

- [d:r:i] Accept.
- [e:c+i] The review is right that the current triadic comparison model leaves runtime/harness code in a back-foot position when it should be a front-foot evidence family.

### 2. Proposal Space Is Too Narrow

- [d:r:i] Accept.
- [e:r:i] The current plan set does not yet evaluate alternatives like `execute-and-learn` or `harness-code-first` seriously enough.

### 3. The `04-17` Bridge Audit Should Not Be Treated As Untouchable Floor

- [d:r:i] Accept in qualified form.
- [e:r:i] The bridge audit should remain a major input, but its verdict can itself be audited for underreach rather than inherited as a stable minimum.

### 4. Single Cross-Review Outputs Must Stay Demoted

- [d:r:i] Accept.
- [e:c+i] This matches the repo's post-falsificationist comparison doctrine and should be made more explicit in the setup.

## What Is Rejected Or Reframed

### 5. Strict Falsifiability As Blanket Standard

- [d:r:i] Reject as stated.
- [e:r:i] The review is too Popperian at points when it asks that the framing additions in `../planning-notes/SESSION-FRAMING-BRIEF.md` be made strictly falsifiable or else demoted.
- [e:c+i] The live epistemic posture is post-falsificationist, not strict falsificationism. That means challenge, refutation pressure, anomaly accounting, and comparative testing matter, but they do not exhaust how framing claims should be judged. Sources: .planning/readiness/phase-01-rerun/POST-FALSIFICATIONIST-REVIEW-DOCTRINE.md:30, .planning/readiness/phase-01-rerun/POST-FALSIFICATIONIST-REVIEW-DOCTRINE.md:33, .planning/readiness/phase-01-rerun/POST-FALSIFICATIONIST-REVIEW-DOCTRINE.md:52, .planning/readiness/phase-01-rerun/POST-FALSIFICATIONIST-REVIEW-DOCTRINE.md:57.
- [d:r:i] Replace the review's falsifiability demand with a stronger but more fitting standard:
  - framing claims should be contestable
  - they should identify what evidence would materially weaken, revise, or re-situate them
  - they should face rival explanations where applicable
  - they should not be allowed to function as unquestioned premises merely because they are eloquent or local

### 6. Vocabulary Audit Framed As Suspicion Of Doctrine Itself

- [d:r:i] Accept in moderated form.
- [e:r:i] It is fair to ask whether the inherited vocabulary can disguise tame closure, but the review overstates the case when it implicitly treats post-falsificationist language as likely closure-bias amplifier absent further argument.
- [d:r:i] Better question: when does the vocabulary sharpen distinctions, and when does it mask weakness by over-classifying it?

## Revised Standard For Session-Level Framing Artifacts

- [d:r:i] `../planning-notes/SESSION-FRAMING-BRIEF.md` should remain explicitly situated.
- [d:r:i] It should not be judged by strict falsifiability alone.
- [d:r:i] It should instead be judged by:
  - contestability
  - revisability
  - comparative openness
  - explicit weakening conditions
  - vulnerability to rival explanation

## Immediate Consequence

- [d:r:i] Future revisions to this audit setup should implement the accepted structural critiques from the review while replacing strict falsifiability language with post-falsificationist wording that is still demanding.
