This chunk turns the response grammar into a note architecture. Once mixed profiles have to be preserved in prose, a further problem appears immediately: how short can the note be without losing the very tension it exists to carry? The note's answer is clean and unusually practical. Full narrative is too much. Bare label strings are too little. A compact three-sentence shape is enough if it preserves three things: classification, key tension, warranted response. That is a strong answer because it keeps prose from sprawling while refusing to let ambiguity disappear into notation.

The next section then protects that compact form from a familiar corruption. Longer notes should not be earned by importance, intensity, or prestige. They are earned only when the compact form would hide something treatment-relevant: a contested classification, an unusual ambiguity, a cross-case dependency, schema pressure, a high-force consequence. This is an important criterion because it stops length from becoming a proxy for seriousness. Extra prose is justified only when it prevents a specific distortion.

That in turn raises the comparability problem. If some notes stay short and others grow, how do the longer ones avoid becoming mini-essays with private logics? The note's answer is layered structure. Every note keeps the same three-part core. Longer notes add only named expansion blocks. This matters because comparability is not sameness of length. It is sameness of spine. A later reader should always be able to recover the classification, the mixed tension, and the response, then see which extra block was needed and what treatment-relevant function it served.

The final move in this slice is equally careful. The expansion blocks themselves cannot be either fully fixed or fully open. A fixed set would force emerging pressures into old shapes. A totally open set would dissolve comparability by letting each case invent its own architecture. So the note chooses the same middle discipline it has chosen elsewhere: sparse by default, revisable under pressure. A new block is justified only when it performs a function no current block can carry without distortion. This is not stylistic novelty. It is architectural insufficiency. The block set, in other words, should evolve only where the current note architecture is failing to preserve a treatment-relevant distinction.

This chunk therefore gives the note a small but load-bearing doctrine of written form. Mixed cases need a minimum prose skeleton. Longer notes need an earned reason. Comparability depends on a common core rather than equal length. Expansion blocks are allowed, but only as functional additions under pressure, not as decorative growth. If I extend the point, I would say that the slice is treating prose itself as a governance surface: too little structure and ambiguity disappears, too much and the note becomes a bureaucracy of elaboration. That phrasing is mine, but it follows the sequence closely.

# Operational Translation

## Three-Sentence Core

Textual pressure: mixed profiles need prose explanation without turning every case into full narrative.
Interpretive translation: a compact note is sufficient when it preserves classification, key tension, and warranted response.
Audit-design implication: make those three elements the default core of every mixed-case note.
Scope: note format and case inscription.
Confidence: high.

## Earned Length Rule

Textual pressure: some cases need more than the compact core, but importance alone is not a justification.
Interpretive translation: extra prose is warranted only when the short form would hide a treatment-relevant ambiguity, dependency, or schema pressure.
Audit-design implication: require longer notes to identify what specific distortion the compact form would create.
Scope: note-length governance and exception handling.
Confidence: high.

## Common Spine, Variable Extension

Textual pressure: longer notes can destroy comparability if they become private essays.
Interpretive translation: comparability depends on a shared core plus explicit bounded extensions.
Audit-design implication: keep every note anchored in the same core structure, then add only named expansion blocks where needed.
Scope: case-note architecture and cross-case comparison.
Confidence: high.

## Sparse-But-Revisable Block Set

Textual pressure: the expansion-block architecture must preserve comparability without becoming rigid.
Interpretive translation: blocks should be few by default but revisable when cases expose missing functions.
Audit-design implication: allow new blocks only when an existing block cannot carry the needed treatment-relevant function without distortion.
Scope: note schema governance.
Confidence: high.
