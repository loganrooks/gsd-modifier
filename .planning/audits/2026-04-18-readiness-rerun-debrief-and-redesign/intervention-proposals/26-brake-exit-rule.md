## Rule

- [g:r:i] A prep program must exit the brake when all of the following are true:
  1. the currently named blocker class has already been converted into either:
     - executed-and-ratified work
     - explicit bounded remainder
     - or a still-live discriminating test with a clear next lane
  2. the next proposed prep move would not materially:
     - close a named blocker
     - discriminate between live program alternatives
     - or increase intervention yield enough to justify the budget it would consume
  3. continued inward motion would primarily preserve the package from risk rather than expose it to stronger judgment
  4. the execution-capacity model has not been explicitly reopened downward in a way that makes the stronger move dishonest

## Release Outcomes

- [g:r:i] Exiting the brake does not mean `proceed by default`. It means the program must choose an explicit release path:
  - proceed under the recomputed rerun floor
  - switch to bounded `Proposal F`
  - switch to `Proposal C`
  - switch to `Proposal E`
  - or record a new blocker class that genuinely reopens preparatory work

## Anti-Misread Rules

- [g:r:i] This is not a `move fast anyway` rule.
- [g:r:i] This is not a schedule-over-truth rule.
- [g:r:i] This does not license ignoring explicit blocking findings.
- [g:r:i] This exists to stop the package from protecting itself through indefinite preparatory recursion after the currently active blocker has already been narrowed as far as the evidence justifies.
