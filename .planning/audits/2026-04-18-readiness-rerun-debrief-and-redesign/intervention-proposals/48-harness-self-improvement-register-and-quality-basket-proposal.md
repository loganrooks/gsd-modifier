# Harness Self-Improvement Register And Quality Basket Proposal

## Purpose

- [g:r:i] This proposal defines the standing self-improvement family exposed by the full-field harness-improvement map.
- [g:r:i] The target is to give the harness a durable place to keep improvement pressure, ownerless concerns, and cross-dimensional judgment visible after any one audit subtree ages.

## Proposed First Slice

- [d:r:i] Add one durable register outside the current audit subtree:
  - `.planning/HARNESS-IMPROVEMENT-REGISTER.md`
- [d:r:i] The register should carry:
  1. active improvement families
  2. ownerless concerns that still need stable routing
  3. bounded next slices
  4. held-later families
  5. a cross-dimensional quality basket for reading tradeoffs across:
     - maintainability
     - robustness
     - propagation visibility
     - operator legibility
     - update resilience
     - lifecycle carry
     - auditability
     - intervention yield

## Why This Family Matters

- [d:r:i] Right now the improvement field is visible mainly because this audit subtree is doing active work.
- [d:r:i] Without a durable register, that field risks dissolving into scattered proposal notes when this subtree ages.
- [d:r:i] A standing register would make it easier to keep improving the harness as a system rather than only as a sequence of disconnected slices.

## What This First Slice Does Not Do

- [d:r:i] It does not try to score everything.
- [d:r:i] It does not freeze one final ranking.
- [d:r:i] It does not replace family-specific proposals or audit outputs.
- [d:r:i] It does not require automation or telemetry in the first slice.

## Held For Later

- [d:r:i] Later growth may add:
  - usage telemetry
  - vintage / decay signals
  - stronger owner mapping
  - richer cross-vendor reviewer-pattern carry
- [d:r:i] The first slice should stay compact and governance-facing.

## Current Consequence

- [d:r:i] If accepted, this family should follow the canary and audit-program infrastructure families so the harness keeps a durable self-improvement memory rather than relying on the lifespan of this one audit subtree.
