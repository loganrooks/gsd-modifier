# Onboarding

## What This Workspace Is

- [g:r:i] This is a debrief-and-redesign workspace for the readiness initiative.
- [g:r:i] It is not a generic retrospective, not a docs-only follow-up, and not a permission slip to restart Phase 01 immediately.

## What A New Reviewer Should Understand First

1. The readiness package was trying to make the harness better at carrying doctrine, future-preserving seams, and stronger review posture into everyday planning and delegation.
2. The `04-17` audit already established that upstream docs are useful but uneven, and that the right move is revision via guarded hybrid reseed rather than either full restart or no change.
3. The later docs work materially improved the available upstream terrain map, but it did not by itself settle how readiness should be rerun or redesigned.
4. The present task is therefore to debrief the first attempt, audit its underreach, compare old mapping against stronger current mapping, and design the next attempt without repeating the same closure bias.
5. The past is an inheritance problem, not a sovereign template. This workspace is partly about deciding what to preserve, what to reinterpret, and where a real break is needed.

## Key Distinctions To Keep Straight

- `readiness package`
  The original governance/process/rerun-readiness effort under `.planning/readiness/phase-01-rerun/`.

- `04-17 bridge audit`
  The comparison between upstream docs and readiness-era mapping that concluded `revise + guarded hybrid reseed`.

- `revised docs work`
  The later `04-17` continuation that improved the upstream docs architecture and created a stronger current terrain map candidate.

- `better mapping`
  Not a file set we already possess. A moving target describing the intervention-ready understanding we still want.

- `critical inheritance`
  The work of sifting prior doctrine, mappings, verdicts, and workflow assumptions so that the next iteration is answerable to the past without being ruled by it.

## Anti-Misread Rules

- Do not assume the old readiness package was simply wrong because it underreached.
- Do not assume the improved docs corpus is automatically sufficient because it is better.
- Do not assume a recommendation for `no new lane` or `no change` is modestly safe; it may simply be under-argued.
- Do not let current Checkpoint 5 status disappear just because this workspace is future-facing.
