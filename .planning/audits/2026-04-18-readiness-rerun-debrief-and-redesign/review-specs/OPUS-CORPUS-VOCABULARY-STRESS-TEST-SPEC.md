# Opus Corpus Vocabulary Stress-Test Spec

Status: drafted for launch  
Reviewer target: `Opus 4.7 Max` via Claude Code CLI `opus[1m]` `max`  
Output mode: single markdown artifact

## Purpose

- [g:r:i] This is not a rewrite lane.
- [g:r:i] This is not another abstract resituation pass.
- [g:r:i] This lane exists to test whether the commentary corpus changes judgment on concrete readiness-era cases, or mostly produces a richer retrospective vocabulary.
- [g:r:i] The lane should pressure-test whether any corpus distinction earns operational inheritance beyond disciplined prose plus existing repo doctrine.
- [g:r:i] The lane should be treated as challenge input, not sovereign doctrine.

## Lane Question

Does the commentary corpus's new or sharpened vocabulary materially change what can be said about a small set of real readiness-era cases compared with what existing repo doctrine, `CLAIM-TYPES.md`, and disciplined prose already carry?

More concretely:

1. What can be said about each case using the existing repo vocabulary alone?
2. What changes, if anything, once the commentary corpus is brought in?
3. Are those changes:
   - a changed recommendation
   - a changed warrant with the same recommendation
   - a salience shift only
   - or philosophical rephrasing
4. Which corpus distinctions, if any, earn partial inheritance on this evidence?

## Method

### Stage 1: Baseline Reviews Without Corpus

For each case:

1. Read the case materials plus the baseline doctrine surfaces.
2. Write a `without-corpus` review using only:
   - the case materials
   - `CLAIM-TYPES.md`
   - `POST-FALSIFICATIONIST-REVIEW-DOCTRINE.md`
   - disciplined prose
3. State:
   - the case's operative move or verdict
   - what the baseline vocabulary can already say about it
   - what recommendation or disposition follows
   - what remains open, deferred, or contested

### Stage 2: Corpus-Inflected Rereads

After all three baseline reviews are drafted:

1. Read the Stage 2 corpus packet.
2. Reread each case through whatever corpus distinctions actually matter.
3. Do not force every candidate distinction into every case.
4. For each case, state:
   - which corpus distinctions were actually used
   - what they changed, if anything
   - whether they changed the recommendation, the warrant, or only the descriptive sharpness

### Stage 3: Comparative Classification

For each case, classify the delta between `without-corpus` and `with-corpus` as exactly one primary outcome:

- `changed_recommendation`
- `changed_warrant_same_recommendation`
- `changed_salience_only`
- `rephrasing_only`

Then defend the classification.

### Stage 4: Inheritance Judgment

Across the three cases, sort each corpus distinction actually used into:

- `earned_partial_inheritance`
- `earned_reflexive_only_inheritance`
- `earned_nothing_on_this_evidence`

If a distinction appears in more than one case with different results, say so explicitly.

## Anti-Misread Rules

- [g:r:i] If the corpus language sounds sharper but changes no recommendation and no warrant, classify it as `rephrasing_only`, not as operational gain.
- [g:r:i] If the corpus preserves the recommendation but changes the burden structure, failure-mode diagnosis, or residual-open handling, that may count as `changed_warrant_same_recommendation`.
- [g:r:i] Do not smuggle a changed recommendation through a rhetorical re-description.
- [g:r:i] Do not punish the baseline unfairly by pretending disciplined prose is weaker than it is.
- [g:r:i] Do not reward the corpus unfairly merely for naming something more elegantly.
- [g:r:i] Do not infer from one successful case that a distinction now deserves repo-wide doctrine promotion.
- [g:r:i] Do not infer from one failed case that the whole corpus is worthless.

## What This Lane Must Not Silently Assume

- [g:r:i] Must not assume the existing claim-type system is the final ontology.
- [g:r:i] Must not assume a sibling analytic layer is necessary.
- [g:r:i] Must not assume the best test is whether the corpus uses more sophisticated language.
- [g:r:i] Must not assume the bridge-audit conclusion is either obviously right or obviously prelicensed.
- [g:r:i] Must not assume preserved openness is either automatically good or automatically conservative.
- [g:r:i] Must not assume that governance/doctrine carriers are either merely indirect or automatically first-wave edit targets.
