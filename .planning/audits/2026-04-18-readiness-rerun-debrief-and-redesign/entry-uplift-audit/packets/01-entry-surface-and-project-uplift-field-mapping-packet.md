# Entry Surface And Project Uplift Field-Mapping Packet

## Purpose

- [g:r:i] This packet gives the widening lane a local scaffold for the entry-surface family before it attempts to widen the map.
- [g:r:i] The task is not to ask whether current onboarding “works.” The task is to map the full field of entry, re-entry, and uplift surfaces; add what the local map still misses; sharpen interactions; and refine where a dedicated uplift workflow should live.

## Operator Rules

- [g:r:i] Map the whole field before narrowing.
- [g:r:i] Do not collapse the task into top-few ranking first.
- [g:r:i] Do not ask or answer in gate-approval shorthand or pseudo-positive deficit shorthand.
- [g:r:i] Distinguish creation, continuation, recovery, migration, and uplift ownership instead of flattening them into one generic onboarding bucket.
- [g:r:i] Name where current ownership is already strong, where it thins, and where work is currently scattered across multiple surfaces.
- [g:r:i] When proposing stronger ownership, keep the split visible between:
  - what current surfaces should continue to own
  - what a later dedicated uplift workflow should own

## Desired Output Shape

- [d:r:i] The lane should return a full-field map, not only a shortlist.
- [d:r:i] It should widen the local map by:
  - adding missing surfaces or scenarios
  - sharpening interactions and propagation paths
  - refining the ownership split
  - identifying report/governing carriers a later uplift workflow should create or refresh
  - clarifying what later widening should still stay out of the first uplift slice
