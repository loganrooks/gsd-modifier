## Runtime-Visibility Tool Judgment

**Shape is correct for the purpose.** [d:r:i] The paired pattern serves both intervention-planning one-shot use and durable audit persistence without forcing either. SHA256 of raw, normalized, and live texts preserves downstream cross-checking without bloating the report. The four-class classifier correctly prioritizes the pilot's core insight — live-only surfaces are usually overlay-scope issues, not mystery drift. No stronger narrow shape is visible from the packet.

**Three narrow design weaknesses have stronger alternatives available.**

- **Missing `obsolete live residue` detection.** [d:r:i] Stronger alternative: a fifth classification branch keyed on `live_exists and not overlay_exists and not in_manifest(rel_path) and not in_backup_meta(rel_path) and not in_install_mutation_targets(rel_path)`. All four input sources are already in the repo: `.codex/gsd-file-manifest.json` (files dict), `.codex/gsd-local-patches/backup-meta.json` (carried-subset), `scripts/setup-portable-gsd.sh` (mutation targets around lines 46–86), and the existing live tree. Implementing this splits the 161-entry `selective overlay boundary` bucket into two — genuinely selective vs. actual residue — which is the precise discrimination later cleanup work needs. Why stronger: it turns the largest, most ambiguous bucket into two discriminable populations without reopening any semantic contract.

- **No `repo-local config carry` rule for `workflow`, `reference`, or `bin_lib`.** [d:r:i] Stronger alternative: extend `classify` with a narrow path-targeted rule set (specific filenames known to carry repo-local edits, paired with a normalized line-set diff that recognizes localized patches rather than file equality). Narrower than semantic diffing, stronger than the current "anything non-equal is unknown" collapse. Why stronger: it prevents `unknown live drift` from absorbing false positives the moment a workflow accumulates a deliberate repo-local patch.

- **No test harness for the classifier.** [d:r:i] Stronger alternative: a `tooling/codex/tests/runtime_visibility/` fixture tree exercising each classification branch plus the two normalization rules. Small bounded work. Why stronger: it is the difference between a tool that reports one number on the day it lands and a tool whose behavior future upgrades can trust. Given the ceremony-risk framing in 09, a silently drifting classifier is itself a carry liability.

**Smaller issues.** [d:r:i]

- `--pretty` help text is not quite what the code does (line 225 makes output pretty when `--pretty` OR no `--output`, not "default true when writing to stdout"). Documentation-level.
- Normalized SHA path-locality needs a metadata line in the report payload.
- Glob shape should either be documented as "flat family directories only" or widened to `**/*` where depth matters.
- `rel_path` should either be removed from the `classify` signature or put to work.

## AGENTS.md -> CLAUDE.md Translation Judgment

**Starting framing.** [d:r:i] This repo's runtime is Codex; `AGENTS.md` is Codex's agent-facing instruction surface. A Claude CLI run does not read `AGENTS.md` automatically — Claude Code reads project `CLAUDE.md` and user/global instructions. The `tooling/codex/` directory already establishes precedent for cross-vendor Claude lanes (see the headless probe notes at [tooling/codex/README.md](/home/rookslog/workspace/projects/prix-guesser/tooling/codex/README.md:6)). So the question is not whether Claude lanes exist in this repo — they do — but what shape a CLAUDE.md equivalent should take so that it carries repo-local authority without duplicating the policy layer.

**Three options, clear tradeoffs.**

- **Direct mirroring — reject.** [d:r:i] Verbatim copy loses earned distinctions. `AGENTS.md:110–113` encodes Codex-native model policy (`gpt-5.4`, `xhigh`, `high`). That policy does not apply under Claude — there is no Codex `gpt-5.4` lane to select in a Claude CLI run. Verbatim mirroring also propagates `~/.codex/state_5.sqlite` launch-truth rules (`AGENTS.md:131–135`) into a file read by a model with no such artifact. The mirror would mislead by omission or by mismatch.

- **Selective translation — partial support.** [d:r:i] Repo-local `CLAUDE.md` carrying only the vendor-neutral policy layer: product posture (§2), runtime canon rules for `.planning/` (§3 minus `.codex/` references), quality bar (§4 — the strongest cross-vendor payload), claim-type grammar pointers to `.planning/CLAIM-TYPES.md`, the headless-probe reciprocal (repo-local path over `/tmp`, explicit permissions), and the runtime-materialization awareness that `runtime_visibility.py` is the canonical visibility surface for intervention-planning work here. Deliberate omissions: Codex model policy, Codex sqlite launch-truth rules, `.codex/get-shit-done` as the Claude runtime, the Codex-specific `spawn_agent` authorization doctrine.

- **Translation plus local wrapper/launcher discipline — strongest available shape.** [d:r:i] Same selective translation, plus a small wrapper: the `CLAUDE.md` carries only the translation delta (what differs under Claude) and points at `AGENTS.md` as the master doctrine for non-vendor-specific rules. The stable policy layer stays in one file; Claude-specific adjustments live in the wrapper. This is stronger than flat selective translation because it prevents the quality-bar text and claim-type grammar from forking into two files that paraphrase apart under later edits. The `tooling/codex/README.md` probe discipline is the working precedent: narrow, Claude-specific, coexists with `AGENTS.md` rather than duplicating it.

**Risks of naive mirroring, ordered by severity.**

1. **Doctrine fork.** [d:r:i] Two files with ~90% overlap drift. The quality bar is where this bites hardest — careful language like "load-bearing gain" vs. "adequate" paraphrases badly under later edits, and nothing keeps two copies aligned except discipline.
2. **Vendor-specific fields leaking cross-vendor.** [d:r:i] `gpt-5.4` and Codex sqlite paths in a CLAUDE.md are doctrinal noise at minimum; they can mislead a Claude run that tries to follow the rules literally.
3. **Launch-truth divergence.** [d:r:i] Codex has `state_5.sqlite`; Claude has no equivalent. A mirror naming Codex launch-truth discipline as universal will either be silently ignored (weakening the rule) or will trigger fabricated equivalents.
4. **Agent-spawn authorization mistranslation.** [d:r:i] Claude Code's subagent model is Task-tool + `subagent_type`, not Codex `spawn_agent`. Copying the authorization clause without translation may over-authorize or fail to authorize Claude's Task subagents cleanly.

**Should this land now?** [d:r:i] The runtime-visibility tranche has no Claude-specific payload and no forcing function. A speculative CLAUDE.md companion is itself ceremony. The stronger move is to wait until a specific Claude lane needs to carry repo-local authority — a scheduled cross-vendor review, a headless Claude audit, a Claude probe required to follow repo-local policy — and then translate bounded by that lane's actual need, in the wrapper shape. The precedent for writing "what not to do under Claude" already exists in the probe README and is the right pattern to extend when the time comes.
