## Gaps Or Overclaims In The Current Register

- [d:r:i] The register understates how much long-horizon carry already exists above the discuss/plan chain. A stronger formulation would explicitly name the four-layer stack: canon doctrine, instruction doctrine, steering-brief construction, and plan-contract enforcement. Without that, the field looks more front-loaded and more fragile than it actually is.
- [d:r:i] The verification gap is real, but the current register risks over-burdening the verifier if read too literally. `verify-phase` is a legitimate gate surface. The stronger replacement formulation is: add a bounded future-preservation review block or a paired carry-review artifact at phase close, rather than converting the entire verifier into a whole-field long-horizon audit.
- [d:r:i] The `SPEC` gap is real but should be narrower than "make SPEC look like CONTEXT." `SPEC` should gain a minimal doctrine-sensitive slot or required doctrine-ref hook for cases where future-aware constraints materially shape the meaning of the phase. Duplicating full `future_awareness` there would blur the WHAT/HOW split that the spec surface was designed to create.
- [d:r:i] The `STATE.md` and `progress` gap is also real but needs a bounded formulation. Because `STATE.md` is a digest with a hard size constraint and `progress` is a compressed report surface, the stronger replacement is "add a compact horizon watch and pointer" rather than "embed a seam register."
- [d:r:i] The register is too light on archive pressure. The highest-risk carry loss is not only that later workflows fail to verify seams; it is that milestone close/open rewrites or deletes milestone-scoped artifacts without a doctrine-carry mechanism. That deserves to be a first-rank pressure family in its own right.
- [d:r:i] The register is too light on canonical-reference loss. The strong `canonical_refs` contract at discuss/plan entry has no later lifecycle analog, so authority drift is not only a seam-preservation problem. It is also a reread-discipline problem.
- [d:r:i] The seed claim should be sharpened. The issue is not merely that seeds are "idea-shaped." The more exact claim is that the current seed pathway is well-shaped for milestone-goal recall and poorly shaped for preserve-only seam activation or doctrine-reopen triggers.
- [d:r:i] The "no explicit harness self-improvement loop" claim is directionally right but slightly overstated if it is read as "the doctrine does not exist." The stronger formulation is: self-improvement pressure already exists in repo doctrine, but it has not yet been operationalized into recurring workflow surfaces at the main lifecycle boundaries.
