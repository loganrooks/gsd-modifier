# Audit Subtree Aging And Graduation

## Purpose

- [g:r:i] This note governs how audit subtrees in this workspace continue to carry force, thin into companion status, or move out of the active path.
- [d:r:i] It exists so audit subtrees do not remain permanently ambiguous after their primary widening or implementation work has already moved elsewhere.

## Status Vocabulary

### Active lane

- [d:r:i] Use when the subtree is still producing new primary lane work or immediate follow-through.

### Active companion

- [d:r:i] Use when the subtree is not the current frontier, but still routes later work through a stable baseline or durable reread set.

### Aging companion

- [d:r:i] Use when the subtree still matters as context or comparison, but most of its reusable doctrine has already been absorbed elsewhere.

### Superseded trace

- [d:r:i] Use when a later family or later lane explicitly replaced the subtree's routing role.
- [d:r:i] Keep it readable as trail, but do not keep pointing new work there as the default entry.

### Archived trail

- [d:r:i] Use when the subtree is retained mainly for historical scrutiny and explicit backward pointers.

## What Changes A Subtree's Status

- [d:r:i] Whether it still routes current next actions.
- [d:r:i] Whether its reusable doctrine has already been absorbed.
- [d:r:i] Whether a later subtree or family now owns the live question.
- [d:r:i] Whether operators still need this subtree as a default reread path or only as explicit historical trace.

## Graduation Paths

### To canon

- [d:r:i] Reusable rules or helper-backed practice move into governance docs, helper docs, or durable registers.

### To companion

- [d:r:i] The subtree remains in the active family baseline but no longer owns the immediate next move.

### To superseded trace

- [d:r:i] A later subtree or later family now routes the live work, and this subtree remains mainly as historical trail.

### To archived trail

- [d:r:i] The subtree no longer needs routine reread, but explicit backwards pointers should still preserve its place in the reasoning chain.

## Minimum Update Actions

- [g:r:i] When a subtree status changes, update the routing surfaces that control later reread.
- [d:r:i] Minimum updates usually include:
  - subtree `README.md`
  - `CURRENT-STATE.md`
  - `INDEX.md`
  - `ARTIFACT-INVENTORY.md`
  - any family register or companion doc that now owns the reusable carry

## Anti-Patterns

- [d:r:i] keeping every subtree implicitly active forever
- [d:r:i] archiving a subtree without preserving where its absorbed doctrine went
- [d:r:i] letting a subtree remain the default reread path after a later family already owns the live question
- [d:r:i] collapsing aging, supersession, and archival into one blunt label
