# Broader Network Propagation Field Mapping Spec

## Framing

- [g:r:i] Reread the propagation family after the widened carrier split in `08`.
- [g:r:i] The governing task is not to restage the project-uplift example, not to collapse the question into install coherence alone, and not to reduce the family to a generic “did we update enough?” verdict.
- [g:r:i] The governing task is to map the broader propagation field as it now stands:
  - how the current carrier families divide
  - what each family currently carries
  - what adjacent carriers still deserve stronger placement or clearer routing
  - what relations among the families remain under-disclosed
  - which bounded next routes would most strengthen the network-carry architecture from this widened baseline
- [g:r:i] Keep the review out of threshold language, deficit-only framing, and binary accept/reject shapes.

## Primary Questions

1. How does the current broader propagation field now divide across:
   - governing doctrine
   - runtime install and materialization
   - runtime registry and launch authority
   - workflow / template / reference contracts
   - skill / wrapper routing
   - helper -> durable output chains
   - governance and audit carriers
2. Which parts of that field are already mapped with strong enough separation that later operators can see propagation duties clearly?
3. Which important carrier families, adjacent surfaces, or propagation relations still deserve stronger disclosure, sharper boundary-setting, or clearer routing?
4. Where do the current docs and tooling already make propagation easier to see, trace, and carry forward?
5. Where do they still compress too much, blend distinct duties together, or leave too much for memory and intuition?
6. Which bounded strengthening routes now make the most sense from this widened baseline?
7. Which wider families should remain explicit later work rather than being silently absorbed into the current propagation family?
8. How should this broadened propagation family now be inherited locally?

## Required Output Shape

Use these exact section headings:

1. `How The Current Broader Propagation Field Now Divides`
2. `What The Current Field Already Makes Easier To See And Carry`
3. `Where Carrier Placement Or Boundary-Setting Still Thins`
4. `What Relations Still Deserve Stronger Disclosure`
5. `Bounded Strengthening Routes From The Widened Baseline`
6. `Wider Families To Keep Explicit Later`
7. `How This Broadened Propagation Family Should Be Inherited`

Inside section `7`, separate:
- `Carry Forward`
- `Strengthen Next`
- `Hold Explicit`

## Review Discipline

- [d:r:i] Map the full field before narrowing to a next sequence.
- [d:r:i] Keep carrier families distinct rather than collapsing them into a single propagation scorecard.
- [d:r:i] If you think a family split is still too blended, name the stronger split.
- [d:r:i] If you think a missing surface deserves inclusion, name the surface and the kind of carry it should own.
- [d:r:i] If you think current docs or tooling still under-disclose propagation relations, name the stronger disclosure route rather than only noting a weakness.
- [d:r:i] If you think a wider family should still wait, keep that hold explicit instead of implying a silent veto.
