## Stronger Design For The Propagation Registry Family

- [d:r:i] The stronger design is a federated registry family, not a single file that tries to carry roster truth, contract truth, runtime truth, semantic meaning, and inheritance state all at once.
- [d:r:i] The first component should be a maintained seed pack:
  - upstream shipped-surface roster seed from `docs/INVENTORY.md`
  - local maintained-doc seed for repo-local doctrine, tooling inventory, workspace governance, and other non-upstream carriers
  - explicit origin typing such as `upstream-pristine`, `local-overlay`, `install-mutation`, `generated-report`, `observed-runtime`
- [d:r:i] The second component should be a declaration and evidence pack:
  - authored contracts such as `OVERLAY-MANIFEST.json`
  - materialization verification outputs from `portable_gsd_contract.py`
  - runtime observation snapshots from `runtime_visibility.py` and launch-truth capture
  - producer-scoped memory surfaces such as `UPLIFT-MANIFEST.json`
  This pack should carry narrow claims plus provenance, not semantic edges.
- [d:r:i] The third component should be the AI-authored semantic registry:
  - canonical family rows
  - canonical carrier rows
  - typed edge semantics
  - propagation obligations
  - direct-consumer versus mirror versus control-surface distinctions
  - explicit `held`, `open`, or `projected` relation markers where the field is not yet closed
- [d:r:i] The fourth component should be operator-control surfaces:
  - scoped reread suggestions by change type
  - semantic diff between registry snapshots
  - inheritance/disposition records
  - a bounded `what this registry still does not claim` surface
- [d:r:i] In that design, the maintained inventory frontier owns shipped-surface roster truth, the prose propagation family owns semantic decomposition and rationale, generated or validated artifacts own bounded proofs and observations, and inheritance artifacts own local carry force. That division broadens control without collapsing back into prose-only memory or code-only extraction.
