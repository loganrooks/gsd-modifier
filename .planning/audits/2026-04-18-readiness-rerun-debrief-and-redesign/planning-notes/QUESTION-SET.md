# Question Set

## Mission Reconstruction

- What was the readiness package actually trying to do?
- What was its theory of change at the level of governance, harness behavior, review posture, and future-preserving planning?
- Which parts of that mission were explicit in artifacts, and which were implicit but load-bearing?

## Outcome And Underreach Audit

- What did the package genuinely achieve?
- What did it produce that was mostly procedural churn, review recycling, or local optimization?
- Where did earned doctrine get translated back down into `safe enough`, `patch lightly`, or other tame closure forms?
- Where did it optimize for limiting disruption rather than maximizing attainable improvement?

## Mapping Adequacy Audit

- How good was the package's actual map of:
  - the GSD harness
  - the Codex / Claude harness
  - the interaction surfaces between them
  - side workflows, branch paths, loops, templates, helpers, and producer-consumer chains
- Where did the original readiness mapping, the bridge audit, and the later docs corpus agree with each other while still diverging from runtime / harness behavior?
- Which important surfaces were invisible, flattened, or underweighted?
- Which interventions were likely under-imagined because the map was weak?

## Comparative Mapping Audit

- How do these compare:
  - original readiness mapping-from-deployment
  - the `04-17` guarded-hybrid comparison result
  - the improved docs corpus produced during the later `04-17` work
  - runtime / harness code and workflow behavior
  - the still-needed intervention-ready map
- Which mismatches were really `docs defects`?
- Which mismatches were really `readiness mapping defects`?
- Which mismatches were really `bridge-audit inheritance defects`?
- Which mismatches were really `docs-and-maps both missed the runtime` defects?
- What still separates current mapping from a map strong enough to support ambitious structural intervention?

## Critical Inheritance Audit

- Which parts of the readiness package remain load-bearing and should be preserved?
- Which parts should be retained only after reinterpretation or reframing?
- Which parts should be explicitly superseded because they are now weaker than the alternatives we have earned?
- Which parts of the past are still being treated as authoritative only because they arrived first?
- Was the bridge audit's own `revise + guarded hybrid reseed` verdict itself too tame, too local, or too quickly inherited as a floor?
- If the `04-17` bridge audit had never happened, what rerun-design proposal would we write now?
- What kind of break with the old package is actually justified, and what kind would simply discard earned doctrine?

## Suppressed Opportunity / Anti-Regret Audit

- Which promising interventions were prematurely excluded, narrowed, softened, or deferred?
- Which recommendations for `leave it local`, `leave it alone`, or `no new phase` were actually under-mapped recommendations in disguise?
- Where did the package likely leave meaningful gains on the table because it treated disruption cost as more salient than future upside?
- Which futures or adaptation paths were preserved, and which may have been quietly foreclosed?
- Which at-least-three stronger interventions were actually considered and rejected in this lane, and what regret analysis justified each rejection?

## Rerun Design Audit

- If the readiness effort were restarted now, what should change in:
  - sequencing
  - lane structure
  - corpus packeting
  - burden of proof
  - comparison method
  - mapping prerequisites
  - review posture
  - execution-capacity assumptions
- Should the rerun start with:
  - debrief-first
  - mapping-first
  - balanced preparatory phase plus main wave
  - execute-and-learn
  - harness-code-first
  - some other shape
- Which new subphases, insertion points, or bridge phases are justified?
- What explicit execution-capacity model is each rerun-shape recommendation assuming?

## Audit-Governance Reflection

- What did the first attempt teach us about how to audit an audit initiative without reproducing its closure bias?
- What standing rules should govern future doctrine-sensitive audit programs here?
- Which guardrails should exist before delegating the next main audit wave to external agents?
- Which framing claims are carrying too much unearned authority, and what evidence or rival explanation would materially weaken, revise, or re-situate them?

## Required Output Registers

Any serious lane or later synthesis should include, where applicable:

- `theory-of-change summary`
- `inheritance-disposition matrix`
- `element-granular inheritance-disposition matrix for top load-bearing artifacts or doctrines`
- `mapping-confidence register`
- `suppressed-opportunity register`
- `non-intervention ledger`
- `interventions considered and rejected ledger`
- `future-preservation judgment`
- `rerun-prerequisites list`
- `recommended next-program options`

## Generative Anti-Tame Quota

- [g:r:i] Every serious main-wave lane should identify at least `3` stronger interventions it considered and rejected.
- [g:r:i] For each rejected intervention, the lane should name:
  - why it was considered
  - what upside it might have delivered
  - what regret analysis counted against it
  - what later signal or evidence would justify reopening it
- [g:r:i] A lane that cannot name rejected interventions should say whether that is because the lane was too narrow to generate them or because it may have under-searched the opportunity space.

## Burden-Of-Proof Rules

- [g:r:i] Any recommendation that says some surface should remain untouched, remain local, or remain out of scope must answer:
  - was the surface mapped well enough to judge?
  - what upside was considered and rejected?
  - what opportunity cost does non-intervention carry?
  - what execution assumptions made the stronger option seem unattractive?
  - what trigger would reopen the question later?
- [g:r:i] Any recommendation that says some surface should be modified, widened, promoted, or added must answer:
  - what futures or adaptation paths does this intervention make harder, more expensive, or less reversible?
  - what reversal cost does the intervention create if it turns out to be wrong?
  - what evidence, anomaly, or later signal would count against the intervention strongly enough to reopen it?
  - what narrower alternative was considered and rejected, and why was that rejection worth the added closure pressure?

## Framing-Pressure Rule

- [g:r:i] Framing artifacts and session briefs should not be treated as unquestionable premises.
- [g:r:i] The right test is not strict falsifiability in every case.
- [g:r:i] The right test is whether the framing:
  - is contestable
  - identifies what would materially weaken or revise it
  - faces plausible rival explanations where those exist
  - remains open to anomaly pressure rather than merely organizing it away
