# First Overlay Rehome Reread

## What The Landed Slice Clarified

Authoritative source now lives under `harness_modifier/overlay/get-shit-done/workflows/{uplift-project,propagation-review,seed-migration-inventory}.md` and `harness_modifier/overlay/skills/{gsd-uplift-project,gsd-propagation-review,gsd-seed-migration-inventory}/SKILL.md`; stable install targets still live through `tooling/portable-gsd/overlay/OVERLAY-MANIFEST.json`; the per-entry `{ "mode": ..., "source": ... }` shape in the manifest now binds those two surfaces with typed indirection instead of relying on physical co-location under `tooling/portable-gsd/overlay/`.
- The contract helper now treats "where the source-of-truth file lives" and "where the overlay writes into `.codex`" as distinct, typed inputs. `normalize_overlay_manifest_entry` and `overlay_entry_source_path` in `harness_modifier/contract/portable_gsd_contract.py` are the load-bearing change: default source still resolves to `tooling/portable-gsd/overlay/<rel_path>`, but any entry can override via `source`, and the resolver hands back an absolute path that the applier and verifier consume identically. That is the first structural proof that the default and the modifier-owned source can coexist inside one manifest without forking the contract.
- The three specialist workflow shells now carry a portable reference grammar (`__PROJECT_ROOT__` token plus package-owned helper shims at `harness_modifier/overlay/helpers/{project_uplift,audit_refmap,seed_migration_inventory}.py`) instead of raw `tooling/codex/*.py` call-sites. Rendering still substitutes `__PROJECT_ROOT__` at install time, so the source file itself is host-path-neutral even though the materialized file under `.codex/get-shit-done/workflows/uplift-project.md` ends up pointing at an absolute host path into `harness_modifier/overlay/helpers/`.
- The scan-plus-roster discipline from `146` has now been exercised end-to-end: the live blockers named there (host audit-workspace embeds, helper-home drift) have been abstracted on the three specialist shells, and the remaining blockers have been pushed cleanly out to overwrite-family shells, continuity references, runtime/agent carriers, and compact-prompt bodies. The roster now labels the specialist trio as `modifier-owned-source` explicitly and keeps the other 72 overlay entries as shared-boundary or host-local.

## What Changed In The Authority Map

- Source authority: for the specialist trio, `harness_modifier/overlay/...`. For the remaining 72 entries, the default authority is still `tooling/portable-gsd/overlay/<rel_path>` because they do not override `source`. That is now an explicit authority split per-entry rather than a whole-overlay rule.
- Install target authority: `tooling/portable-gsd/overlay/OVERLAY-MANIFEST.json`. The manifest file itself did not move; only some entries changed shape. Install-target identity under `.codex/` is unchanged — `.codex/get-shit-done/workflows/uplift-project.md` is still the same materialized path it was before the slice.
- Materialization and validation authority: `harness_modifier/contract/portable_gsd_contract.py`, working against the same `OVERLAY-MANIFEST.json`. This means one contract helper now governs both default-source and modifier-owned-source entries. The verifier, applier, capture-pristine, and strict-mode checks now operate on typed `{mode, source_rel_path, source_path}` rather than implicit `overlay_root + rel_path`.
- Runtime horizon: unchanged. `.codex` remains the observed runtime basis, `.claude` remains the held annotation, per `harness_modifier/compatibility/declaration.json`. The slice did not widen the runtime horizon; it clarified the source side of the install path.
- Compatibility declaration and parity-scan baseline: unchanged by this slice. They remain anchored to `.codex` with `.claude` as annotation, and they still route through `harness_modifier/compatibility/` rather than `tooling/codex/`.

## Propagation And Override Implications

- The per-entry `{ "mode", "source" }` shape is now a contract surface in its own right. Later overwrite-family entries that want to exercise source indirection will need capture-pristine, validate-manifest, and verify-materialized to tolerate non-default `source_rel_path` on overwrite mode. The current slice proved this only for `add` entries. That is a real propagation obligation: the first overwrite-mode source-split move will exercise `load_backup_meta_paths`, the pristine-capture pipeline, and the post-materialization coherence check against a modifier-owned source for the first time.
- Setup entry point `scripts/setup-portable-gsd.sh` is now a consumer of this new contract shape (validate-manifest, apply-overlay, capture-pristine, verify-materialized all run through `harness_modifier/contract/portable_gsd_contract.py`). The setup path is the single real override lever for "do install coherence checks still pass when source authority moves?" That lever is now exercised for the `add`-mode specialist trio; overwrite-mode remains unexercised.
- `__PROJECT_ROOT__` substitution is now load-bearing for host portability of generic workflow shells. `render_overlay_text` replaces both `__PROJECT_ROOT__` and `__COMPACT_PROMPT_FILE__`. That means the source-side host-neutrality of `harness_modifier/overlay/get-shit-done/workflows/*.md` depends on this token substitution, and skill-adapter files that bypass it (by using absolute host paths in `execution_context`) bypass the host-neutrality guarantee.
- Override levers remain three-layered and intact: `PRIX_COMPACT_PROMPT_FILE` env override, `.codex.local/compact-prompt.txt` selector, and `DEFAULT_COMPACT_PROMPT_FILE` contract constant — plus the `OVERLAY-MANIFEST.json` add/overwrite grammar now extended with per-entry `source`. The rehome did not weaken any of them.
- Runtime horizon remains `.codex` with `.claude` as held annotation. No `add`-mode source-split change in this slice increases pressure on `.claude` materialization yet, but the cross-runtime translation question (install `harness_modifier/overlay/...` sources into a future `.claude` target) is now structurally closer to tractable: once the manifest can declare both target runtime and source root, a later `.claude` materialization route becomes a contract widening rather than a new codebase.
- Propagation carrier refresh `55` now names both surfaces in the propagation family. Later change-triggered refreshes in this family should keep naming both (install target + source authority) rather than collapsing them, otherwise the new typed indirection erodes back into implicit co-location inside operator memory.
