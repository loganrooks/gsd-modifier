## Payload-Home Judgment Now

- The payload boundary is materially thinner than the lane-`08` boundary. All three lane-`06` coupling surfaces — policy-data, host-doctrine catalog plus operator-facing vocabulary, and host-planning-shape writer/scanner — are now typed carriers or a typed writer. `project_uplift.py` no longer contains any of the host-shape constants lane `06` named as the relocation blockers. The helper's remaining contents are classification, fingerprint dispatch, analysis composition, drift-reason composition, rendering, progress-note composition, selector-value projection, and a narrow install-contract plus artifact-home pair.
- The payload boundary is still not a clean relocation boundary. Two narrower classes of coupling remain, and each is in a different class from the three discharged surfaces:
  - install-contract wiring (`OVERLAY_MANIFEST_REL_PATH`), which names the current portable-GSD overlay-manifest install target directly in helper code;
  - held-later artifact-home (`tooling/codex/UPLIFT-HELD-LATER.md`), which sits inside the helper's own source tree rather than beside the typed uplift carriers under `harness_modifier/uplift/` or under `.planning/`.
- These two remaining couplings are not of the same weight as the three discharged lane-`06` surfaces. The install-contract pointer is a single path literal the helper consumes as one input, and the held-later artifact-home is a text-catalog file the helper reads once per run. Neither re-declares the host's planning-state topology, host-facing vocabulary, or host-doctrine catalog the way the three discharged surfaces did. Relocating the payload with those two tails still in place would carry a single install-contract literal and a single artifact-home path into the new home rather than re-hosting a host-planning-shape blur one move outward.
- Even so, the sharper next adjacent route is not relocation. Install-contract pointer neutralization is a genuinely narrower bounded slice with its own already-reserved naming (lane `08` and lane `09` both pinned it as the next named later tranche), it has exactly one primary site (`overlay_manifest_rel_path` / `load_overlay_manifest`), and it resolves a class of coupling that is materially different from the three discharged surfaces. Taking it before relocation keeps the install-contract surface typed the same way policy-data is typed, so later payload movement does not carry the install-target literal as helper memory.
- The held-later artifact-home move is a second, adjacent later slice, not a companion to install-contract neutralization. The artifact-home question is where the catalog file should live (still under `tooling/codex/`, beside typed uplift carriers under `harness_modifier/uplift/`, or under `.planning/`), and what the pointer should name once it moves. Bundling it with install-contract neutralization would blur a path-owned typed-carrier move with an artifact-placement move; keeping them distinct preserves the single-axis-per-tranche discipline the three landed tranches now set.
- Ordering inside the later stack therefore stays: (i) install-contract pointer neutralization tranche (`OVERLAY_MANIFEST_REL_PATH` plus whatever narrow install-contract wiring rides with it), (ii) held-later artifact-home tranche as its own narrower sibling after install-contract lands, (iii) only then reopen the payload-home question a fourth time on the further-thinned helper. Relocation, second overlay filesystem tranche, overwrite-family source-indirection widening, standalone repo boundary, packaging, and broader `.codex` / `.claude` parity redesign stay outside this judgment.
- `seed_migration_inventory.py` stays downstream; it still imports `pu` and cannot lead payload-home movement. `harness_canary.py` stays a neighboring consumer that reads the output-policy carrier plus `pu.build_progress_note`; it does not inherit payload-home authority. `audit_refmap.py` stays out of the later payload-movement candidate set per the helper authority map. `.codex` remains observed basis and `.claude` remains held annotation across this lane.
